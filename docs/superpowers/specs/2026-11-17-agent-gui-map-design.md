# 視窗加上地圖：顯示位置與路徑、點地圖叫狗過去 — 設計

日期：2026-11-17
前一份 spec：`2026-11-11-agent-gui-design.md`（那份把「小地圖、在畫面上點選目標」列為非目標，本文件把它補上）。
不改 RL 策略、Isaac Sim 腳本、Nav2 參數、地圖檔。

## 1. 目標

在對話視窗裡加一張公寓地圖，用途有兩個：

1. **看**：狗現在在哪、面向哪邊，導航時 Nav2 規劃出來的路徑。
2. **操作**：在地圖上點一下，狗就走過去。

使用者的決定：
- 點地圖**直接交給 Nav2，不經過 Gemini**：不花額度、點了立刻走、不會被模型誤解。對話區寫一行紀錄；狗不會用中文回覆這一步。
- 地圖放在**右欄上方**，對話區在下方；相機畫面維持在左邊。

### 成功條件

1. 測試全部通過（不需要模擬器、網路；視窗測試用 Qt offscreen）。原有 120 個仍通過。
2. 開著相機的模擬器實測（第 6 節）全部通過。
3. 點地圖不送任何 Gemini 請求。
4. 點到走不到的地方（牆、家具、離障礙物不到 0.30 m）時，狗不動，對話區說明原因。
5. 停止按鈕、關視窗對「點地圖」的導航一樣有效。

### 非目標

- 點地圖時指定到達後的朝向（拖曳出方向）：到達後面向行進方向，和 `go_to_pose` 不給角度時相同。
- 縮放、平移地圖；顯示 costmap、雷射點。
- 點地圖的步驟讓 Gemini 知道（之後問「你在哪」，模型仍會用 `get_pose` 查，答案是對的）。

## 2. 版面

```
┌─ 機器狗 ──────────────────────────────────────────────────────┐
│ ┌──────────────────────────┐ ┌──────────────────────────────┐ │
│ │                          │ │ 地圖：灰底、黑色牆            │ │
│ │        相機畫面          │ │   ● 地點（八個，附名稱）      │ │
│ │                          │ │   ▲ 狗（位置與朝向）          │ │
│ │                          │ │   ─ 路徑（導航中）  ✕ 目標    │ │
│ │                          │ └──────────────────────────────┘ │
│ │                          │ ┌──────────────────────────────┐ │
│ └──────────────────────────┘ │ 對話                          │ │
│ [起點][客廳西側][主臥室][次臥室] └──────────────────────────────┘ │
│ [餐桌旁][廚房][玄關][浴室門口]  [ 輸入指令…            ][送出] │
│ [          停 止          ]                                   │
├───────────────────────────────────────────────────────────────┤
│ 位置 (x, y) 朝向 θ°　區域                     │  狀態          │
└───────────────────────────────────────────────────────────────┘
```

- 右欄：地圖和對話區的高度比約 3:2。地圖保持原本的長寬比（約 5:3），置中。
- 視窗最小尺寸從 1000×600 改成 1100×700。

## 3. 地圖上畫什麼

| 元素 | 畫法 | 資料來源 |
|---|---|---|
| 地圖 | 空地淺色、障礙物深色、未知灰色；y 軸朝上（和 RViz 一樣） | `/map`（定位模式是存好的地圖，建圖模式是正在建的地圖，會隨時更新） |
| 地點 | 八個小圓點，旁邊是地點的短名稱（「廚房」） | `places.PLACES` |
| 狗 | 藍色三角形，尖端指向朝向 | 和狀態列同一個位置（`session.pose()`，每 0.5 秒） |
| 路徑 | 綠色折線 | Nav2 的 `/plan`；只在「處理中」時畫，指令結束就清掉 |
| 點選的目標 | 紅色 ✕ | 點下去的位置；指令結束（到達、被拒絕、取消）後再保留 2 秒才清掉 |

還沒收到地圖時，地圖區顯示「等地圖…（nav.launch.py 開了嗎？）」。`--no-robot` 時改讀 repo 裡的 `maps/apartment.yaml`。

## 4. 點地圖

- 只有狀態是「待命」時可以點；其他時候點了沒有反應，游標也不是手指形。
- 點在地圖範圍外（留白處）沒有反應。
- 點下去：把畫面座標換算成地圖座標，交給 `Session.go_to(x, y)`：
  - 和輸入指令一樣進入「處理中」，一次只執行一件事，地點按鈕和輸入框鎖住，停止可按。
  - 在背景呼叫現有的工具 `go_to_pose(x, y)`：先檢查走不走得到，再交給 Nav2，到達後面向行進方向。
  - 對話區寫一行開頭 `[地圖] 去 (1.20, 0.50)`，結束時一行結果，格式和工具呼叫相同：`  [工具] go_to_pose … → reached`
    （或 `blocked（原因）`、`canceled（canceled by the user）`）。
  - 不呼叫 Gemini，不產生「狗：」的回覆。
- 停止、關視窗的行為和文字指令完全相同（同一個機器人、同一個取消）。

## 5. 程式怎麼分

| 檔案 | 改動 |
|---|---|
| `map_view.py`（新，純 Python + numpy） | `grid_to_gray(data, width, height)`：佔據格（-1/0～100）轉成灰階位元組，並上下翻轉讓 y 朝上；`MapGeometry(resolution, origin, width, height)`：地圖座標 ↔ 格子座標，以及給定元件大小時的縮放與置中（地圖座標 ↔ 畫面像素） |
| `map_feed.py`（新，rclpy） | `MapFeed`：自己的節點和執行緒，訂閱 `/map`（transient local，才拿得到啟動前就發布的地圖）和 `/plan`；`latest_map()`、`latest_path()` 只回最新一份 |
| `map_widget.py`（新，PyQt5） | `MapWidget`：自己畫地圖、地點、路徑、狗、目標；處理點擊 |
| `gui.py` | 版面改成右欄上下兩塊；計時器每 0.5 秒更新狗和路徑，地圖只在換新時重畫；路徑只畫這個指令開始之後才收到的 |
| `session.py` | 新增 `go_to(x, y) -> bool`：和 `submit` 相同的狀態與事件，但直接呼叫 `toolbox.call('go_to_pose', …)` |

依賴不變：`/map`、`/plan` 的訊息型別（`nav_msgs`）已在 `package.xml`。不安裝新套件。

## 6. 驗證

**自動測試**
- `map_view`：灰階轉換（空地、障礙、未知、翻轉）；座標換算來回一致；縮放置中後點在留白處判為範圍外。
- `session.go_to`：狀態和事件順序；不呼叫模型；被拒絕時的紀錄；忙碌時拒絕；停止有效。
- 視窗（offscreen）：點地圖換算出的座標正確並交給 `go_to`；非待命時點了沒反應；路徑在指令結束時清掉；沒有地圖時的提示文字。

**實機檢查**（開相機、定位模式，用驅動腳本操作真的視窗元件，以 `/odom_gt` 判定）

| # | 動作 | 通過條件 |
|---|---|---|
| 1 | 啟動 | 30 秒內地圖出現；地圖上的狗和真值位置相差 < 0.15 m |
| 2 | 點次臥室附近的空地 | 導航途中收到路徑；到達時真值在點選位置 0.25 m 內；整段沒有 Gemini 請求 |
| 3 | 點床的中央 | 對話區出現 `blocked`；沒有送出 Nav2 目標；狗不動 |
| 4 | 點遠處，5 秒後按停止 | 出現 `canceled`；回到「待命」；之後 3 秒移動 < 0.1 m |

另外截一張導航途中的視窗圖給使用者看。

## 7. 留給實作者的決定

- 顏色、字型大小、三角形大小：清楚好看即可，截圖確認。
- 地點名稱若在小視窗中重疊，可以只畫圓點、名稱改成滑鼠移上去才顯示。
- 收到新的 `/map` 時重建灰階圖的方式（建圖模式約每幾秒一次，可以直接整張重建）。

## 8. 結果（2026-11-17）

- 測試 151 個全部通過（原有 120 個加上新增的 31 個；地圖元件和視窗用 Qt offscreen）。
- 實機檢查（第 6 節，`--headless`、開相機、定位模式）4/4，全程 Gemini 請求 0 次：
  1. 0.5 秒出現地圖；地圖上的狗和真值相差 0.007 m。
  2. 點 (2.6, 2.0)：途中收到並畫出路徑；到達後真值離點的位置 0.10 m。
  3. 點 (0.4, 2.7)：`blocked`（不連通）；沒有執行中的 Nav2 目標；狗移動 0.017 m。
  4. 點 (-2.5, -0.3)，路徑出現 5 秒後按停止：`canceled`，回到「待命」，之後 3 秒移動 0.066 m。
- `--no-robot`：點 (2.6, 2.0) 到達，沒有「狗：」的回覆，模型呼叫 0 次。

和設計不同的地方：目標 ✕ 一律在指令結束後保留 2 秒（第 3 節已更新）；地圖元件放在自己的檔案 `map_widget.py`（第 5 節已更新）。
